How it was done

  • Four reviewers in parallel: core receive/send path and spam engine; Compose UI code; build, manifest and security; live UI on the emulator (the phone was locked, so the live pass ran on the spamless35 emulator).
  • Five fix agents in separate git worktrees with non-overlapping files: receivers/messaging, spam engine, theme/thread/app lock, screens/accessibility/UX, manifest/build/CI. Their branches were merged into review-fixes with no conflicts, plus one integration commit.
  • Checks on the merged branch: assembleFossDebug, assembleFossRelease (minified), testFossDebugUnitTest, lintFossDebug: all pass.

Fixed — bugs

Message safety (receive, send, schedule)

  • highIncoming SMS could be lost when the provider insert failed silently; the safety copy is now kept and replayed.
  • highIncoming SMS could be inserted twice by the fallback path; only the provider insert can fail now.
  • highInline reply could go out on the wrong SIM (subscription id read as a list index).
  • highScheduled messages could be deleted without being sent; they are sent on a worker and deleted only after success.
  • medExact-alarm permission missing on Android 12+ silently dropped scheduled messages; inexact fallback plus permission-change handling.
  • medMMS content filter used the default SIM, not the receiving SIM.
  • medMMS push could be lost when the broadcast finished before the library task ran.
  • medA filter crash (Error) could lose every SMS for 7 days; the engine now fails open and expired rows are delivered, not deleted.
  • medBlocked MMS lost its text; "Not spam" now restores the text when it was downloaded.
  • medMissing goAsync() in reply, send-status, mark-read and delete receivers.
  • medConversations DB used destructive migration fallback (would wipe drafts and scheduled messages); removed, instance made @Volatile.
  • lowRace between replay and a slow receiver; "Not spam" double tap; respond-via-message URI parsing; MmsSent null URI; cursor leaks; notification Delete ignored the recycle bin; XML import on the main thread and wrong sent date; legacy SIM extra.

Spam filter accuracy

  • medWithout the contacts permission, STRICT mode blocked every contact silently; now it skips unknown-sender blocking and logs CONTACTS_UNAVAILABLE.
  • medOTP detection: Persian/Arabic digits and keywords, 4–8 digit codes next to a keyword, whole-word matching, links never auto-allowed in SMART.
  • lowNumbers normalised with the receiving SIM's country; regex rules validated (no catastrophic backtracking), body capped, cache bounded; purge throttled; 7-day stats window no longer stale.

UI bugs

  • highCamera photo lost if the app was killed while the camera was open.
  • highCancelling the default-SMS dialog closed the app; now an explanation screen with "Set as default".
  • med"No contacts found" in New conversation; contacts read from the system provider off the main thread.
  • medOTP notification showed three copy buttons; now one.
  • medRestored ("Not spam") message jumped its thread to the top of the list.
  • med"Use English" force-closed the app; now per-app language (AppCompatDelegate).
  • medState lost on rotation: typed recipient, search query, selections, dialog text.
  • lowThread menu offered "Add to contact" for saved numbers; thread onNewIntent restarted the screen and could drop the draft.

Fixed — security and privacy

  • highBackups copied blocked messages, the decision log and the PIN hash; app storage is now excluded from cloud backup and device transfer.
  • highMmsReceiver was exported with no permission (fake MMS injection); now not exported.
  • highApp lock bypass on six screens; lock now enforced centrally for every screen.
  • medPIN stored as unsalted SHA-1 with a 5 s reset; now salted PBKDF2 (100k rounds, migrated on next unlock) with persistent exponential backoff.
  • medRecents thumbnail hidden while app lock is on; fingerprint unlock works again (USE_BIOMETRIC restored).
  • lowMutable PendingIntents made immutable; lock-screen notifications default to sender only for new installs; blocked notification hides spam text on the lock screen; unused permissions removed; three activities no longer exported.

Fixed — native / Google standard

  • Material You dynamic colour is the default on Android 12+; presets set every M3 colour role (no purple leaks); theme changes apply live.
  • System predictive back works on all screens (the commons always-on back handler was the blocker); custom transitions removed so platform transitions apply and RTL is correct.
  • Chat screen uses the same theme as the rest of the app.
  • Activity Result APIs, system Photo Picker, M3 SearchBar, M3 Badge, scroll-aware top bars, BackHandler instead of overrides.
  • Accessibility: labelled FAB (hidden in selection mode), one TalkBack node per bubble, 48 dp touch targets, selected state on theme cards, badges scale with font size.
  • Consistent time formats following the system 12/24 h setting; person avatar for number-only senders; M3 colour roles instead of custom amber; aligned settings rows, clearer block-list grouping; both swipes archive (as in Google Messages); plurals and translatable decision-log labels.
  • Build: Compose BOM 2025.09 → 2026.06, core-splashscreen added, Room schemas committed, Gradle caches on, JitPack restricted, mavenLocal removed, lint/detekt baselines pruned, CI builds and lints the minified release, release workflow refuses unsigned APKs.
  • Repo: CODEOWNERS, issue templates and CONTRIBUTING point to this project; PRIVACY, ARCHITECTURE, FILTER_PIPELINE and CHANGELOG updated.
