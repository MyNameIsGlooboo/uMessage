Spamless

Native Android SMS/MMS app whose main job is to stop spam. Plan v1 · 2026-10-29 · awaiting approval

One-line pitch: a full default-SMS-app replacement (Poco / Redmi / Xiaomi / Samsung / any Android) that, out of the box, blocks every message from numbers not in your phonebook, with whitelist, blacklist, rules, dual-SIM support and a polished Material 3 UI. Fully offline: the app declares no INTERNET permission.

1. Goals and non-goals

Goals
  • Complete messaging app: SMS, MMS, group threads, search, notifications with inline reply, drafts, scheduled send, backup/restore.
  • Core feature: Block unknown senders (not in contacts).
  • Whitelist / blacklist with number, prefix, alphanumeric sender, keyword and regex rules.
  • Real dual-SIM support (receive, send, per-SIM settings and rules).
  • Works well on MIUI / HyperOS (Xiaomi, Redmi, Poco) and One UI (Samsung).
  • Best-in-class UI built with design guidance from the ui-ux-pro-max skill.
  • Private: all data on device, no analytics, no network.
Non-goals / honest limits
  • RCS: Android gives RCS access only to Google Messages and the Samsung stack. Third-party apps cannot send or receive RCS. Spamless is SMS/MMS only.
  • Call blocking is out of scope (SMS only).
  • Google Play requires a special declaration for default-SMS apps. Distribution plan is GitHub Releases APK first; Play Store is a later, separate step.
  • I cannot test on a physical dual-SIM phone from this PC. Logic is unit-tested; final device tests are done by you with a checklist I will provide.

2. Spam-blocking design (the heart of the app)

2.1 Filter pipeline (runs inside the SMS_DELIVER receiver, before anything touches the system inbox)

incoming SMS PDUs
  → assemble multipart, read sender + subscriptionId (SIM)
  → normalize sender (libphonenumber, region from SIM country)
  1. Whitelist match?            → ALLOW  (always wins)
  2. Blacklist match?            → BLOCK  (number / prefix / keyword / regex / alphanumeric)
  3. Sender in contacts?         → ALLOW
  4. Exemption rules match?      → ALLOW  (e.g. OTP keywords, allowed short-codes, "replied before")
  5. Unknown-sender mode:        STRICT = BLOCK · SMART = quarantine/allow by heuristics · OFF = ALLOW
  ALLOW → write to Telephony provider, notify
  BLOCK → store only in Spamless DB (Blocked folder), silent, no notification (optional badge)

2.2 Modes

ModeBehavior
Strict (default, as requested)Everything from non-contacts is blocked unless whitelisted or exempted.
SmartStrict + built-in heuristics (OTP/verification code patterns, known alphanumeric bank/delivery senders you approve) go to an "Unknown" tab instead of being dropped.
OffNo filtering by unknown status. Lists and rules still apply.

2.3 Important edge cases (handled explicitly)

  • Bank / OTP / delivery messages come from non-contacts (e.g. VM-HDFCBK, short codes). Strict mode would hide them. Mitigation: first-run explanation, "Allow this sender" in one tap from the Blocked folder, optional OTP exemption toggle, and a "Recently blocked" quick banner.
  • Blocked is reversible: blocked messages are kept (auto-purge after N days, configurable). "Not spam" restores the message into the real inbox and whitelists the sender.
  • Number formats: +91…, 0…, spaces, dashes, local vs international all normalize to one key.
  • Contacts change: ContentObserver keeps a cached contact set in Room, so filtering is instant and works in the background.
  • Per-SIM rules: each rule and mode can apply to SIM 1, SIM 2 or both.
  • Blocked MMS: same pipeline on WAP_PUSH_DELIVER; blocked MMS are not downloaded, so no data is spent.
  • Never lose a message: receiver is fast, uses goAsync(), and persists to the Spamless DB first (write-ahead), so a crash cannot drop an SMS.

4.1 Default-SMS-app requirements (all will be implemented)

  • Receiver for SMS_DELIVER (permission BROADCAST_SMS) and WAP_PUSH_DELIVER (BROADCAST_WAP_PUSH, MIME application/vnd.wap.mms-message).
  • Activity handling SEND/SENDTO with sms:, smsto:, mms:, mmsto:.
  • Service handling RESPOND_VIA_MESSAGE (permission SEND_RESPOND_VIA_MESSAGE), used by the dialer's "reply with message".
  • Permissions: READ_SMS, SEND_SMS, RECEIVE_SMS, RECEIVE_MMS, READ_CONTACTS, READ_PHONE_STATE, READ_PHONE_NUMBERS, POST_NOTIFICATIONS, CHANGE_NETWORK_STATE, WAKE_LOCK, VIBRATE, RECEIVE_BOOT_COMPLETED, SCHEDULE_EXACT_ALARM (scheduled send). No INTERNET.
  • MMS via platform SmsManager.sendMultimediaMessage / downloadMultimediaMessage with per-SIM subscription and own PDU build/parse.

4.2 Dual SIM

  • SubscriptionManager for active SIM list, slot index, carrier, color; listener for SIM changes.
  • Incoming: subscription id taken from the SMS broadcast extras; stored on each message.
  • Outgoing: SmsManager.createForSubscriptionId(id); compose bar shows SIM chip; default = last used in that thread, else system default SMS SIM.
